# Synthetic PII gold set: accuracy results

Gold set: `pii-synthetic-en-v1.json` (40 synthetic English sentences, 130 spans: NAME 65, DATE 20, LOCATION 15, PHONE 10, ID 10, EMAIL 5, AGE 5; CC0; generated by `scripts/evaluation/generate_pii_gold.py`). Scoring: `medscale_pack::entity_eval`, strict (exact span and canonical label) and overlap (same label, overlapping span), one-to-one, micro-averaged. Each model ran through the product path on free CI: catalog-pinned acquisition, verified signed Pack, local tract or candle runtime.

**Evaluation evidence on a small synthetic set. It is not clinical validation and says nothing about real patient text.**

Runs: accuracy batch 04, run 39116785152 (after the punctuation word-split fix), for 24 models. `OpenMed-PII-QwenMed-XLarge-600M-v1-onnx-android` is from batch 03, run 39110859422 (its batch 04 job was cancelled); for QwenMed the word-level columns predate the fix, which does not affect its tokenizer family.

## Findings

- **Runtime parity:** each model's ONNX export (tract) and safetensors export (candle) score identically in every configuration.
- **Span boundaries dominate:** with the OpenMed-compatible decoding, strict F1 is far below overlap F1. Token-level decoding splits words into several entities.
- **Decoding:** `word_first_pii_merge` (each word takes its first sub-token's label, then OpenMed's PII entity merger) has the highest mean strict F1 and is best for 17 of 24 models. `word_average` is best for 4 and `word_first` for 3.
- **DeBERTa-v3 fix:** batch 03 showed word-level decoding below the default on the SentencePiece SuperClinical models, because their word ids split on whitespace only (`72-year-old`, `2001.` as one word). Treating punctuation-only tokens as words raised `word_first_pii_merge` on those models from 0.51–0.53 to 0.90–0.92 strict F1; every other model is unchanged.
- Core keeps the OpenMed-compatible decoding as the default for parity; `PackEvaluationRequest.decoding` selects the others.
